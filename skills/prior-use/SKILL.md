# Find what is known and what a question would add

Create or update `research/<dataset>/prior_use.md`. Start from the dataset's identity, aliases, collection purpose and version in its documentation or data card; no seed is required. Use the host's search tools and source-reading capabilities, recording queries, dates, source locators and consequential access limits.

1. Find collection/flagship and companion papers, then follow their citation/reuse trail and official publication lists for analyses of these observations. Include owner-reported published or ongoing work for private data; distinguish actual reuse from citations or related datasets.
2. Before choosing leading candidates for deeper investment, save a compact reuse map: source and locator, evidence that these observations were used, subset, question, comparison and claim. Read the relevant methods/results; mark abstract-only, inaccessible and unresolved close sources. If no reuse was found, record where you looked and the limits. Provisional idea generation can proceed while this map develops; source counts do not prove completeness.
3. For promising candidates, use [the precedent guide](references/precedent-hunt.md) to search conceptual equivalents and later work. Save the closest comparisons in `precedents/<candidate>.md`, including the specific contribution left after reading them.
4. After a material reframe, update the affected searches and judge whether it is already answered, a substantive extension, a useful replication, or unresolved. Source inspiration is not novelty evidence; an old limitation does not establish a current gap.

Report “not found within these searches” with scope and limitations rather than asserting novelty from absence. Follow decisive unresolved leads within budget; if an unread close source could reverse the judgment, carry that uncertainty into the candidate's disposition. Return the useful next search and the supported contribution to `discover`.
