# Decide whether and how one question can be answered

Own one `questions/<id>/` directory and write in English. Read the candidate, screening comparison, user intent, three knowledge sources and authorized scope. The coordinator supplies remaining budget and repair allowance. Use [answerability](../references/answerability.md) for scientific checks and [operational definitions](../../dataset-card/references/operational-definitions.md) for deciding measurements. Return shared-source corrections to the coordinator; do not edit other questions or spawn children.

## Resolve the first decision before building the study

Write the question and what an answer would change in `development.md`. Identify the first affordable observation or argument that could change whether this direction deserves deeper planning. Choose it from the actual uncertainty: a closest-source comparison, measurement meaning, local trigger, joint support, equivalence or a small counterexample. Perform it before extensive estimator development or calibration. This ordering is adaptive; data inspection need not precede a decisive source or algebra check.

Explain what the result permits next. Continue if the proposed comparison remains useful and supported enough to develop. If it fails, support a worthwhile reframe or stop that design. If the check is blocked, return its exact effect on the question and a bounded conditional sketch; let the coordinator decide whether this direction merits more budget. Missing access is not evidence of scientific impossibility. Do not postpone an affordable authorized check merely because its outcome might remove the question.

## Develop the surviving scientific comparison

Write `plan.md` around the quantity the question asks about, before choosing a convenient estimator. Explain the closest work and increment, measurements, eligible population and units, ordered computation, weights, uncertainty or identification, and useful positive, negative and inconclusive outcomes. Follow learned inputs, splits and selection through to the reported interpretation. Link checks and their actual scope; an illustrative surrogate does not validate the final procedure. Save code, assumptions and aggregate/synthetic outputs when execution clarifies the decision.

Use [question development](../references/question-development.md) after a material reframe: renew affected value, literature and data evidence and show what changed. Request owner-only facts through the coordinator, preserving earlier answers. Apply the planning boundary to the purpose of each calculation; real target effects, performance or significance cannot choose or rescue the question.

Return supported, conditional, deferred or rejected work with the deciding evidence and next unresolved scientific choice. After review, test the objection and any proposed remedy using [bounded critique](../references/critique.md); identify the new scientific claim before revising. Do not certify your own repair. Budget or cycle exhaustion preserves useful partials without an unchecked replacement.
