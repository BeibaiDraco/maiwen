# Translate the scientific account into a computation

Use this inside the existing plan or final-document review when implementation is consequential. Give the independent reader the current dossier/plan, linked evidence, authorized inputs and scope, with prior verdicts withheld for an initial assessment. Record inaccessible inputs as gaps. Use the remaining review budget; this is not another standing role or a new workflow.

Follow the quantity being estimated from the source records through eligibility, joins, units, transformations, weights, fitting, evaluation, uncertainty and interpretation. Translate it into ordered steps. For a technically ambiguous argument, a small code skeleton or synthetic fixture can expose a gap; otherwise annotated pseudocode is sufficient. Reuse existing tools.

Separate routine implementation choices from choices changing the population, measurement, estimand, model comparison or decision. Make ordinary coding choices and name them briefly. For a missing scientific choice, identify the affected claim and evidence needed; leave that branch pending rather than silently selecting a convenient default. A suggested replacement is a scientific proposal requiring verification.

When exercising code, use authorized structural and synthetic inputs. Test the actual rule and its composition, including a meaningful failure and intended valid case where useful. Record what ran, the procedure revision, inputs and what its result establishes. A surrogate or fixed learned object validates only that conditional computation. Explain the assumptions under which the synthetic calculation succeeds and which real-data conditions remain to be checked.

Apply the [planning boundary](../../dataset-card/references/generic-probes.md#default-planning-scope) by purpose. A skeleton or a check label does not authorize candidate target effects, target prediction, significance or confirmation access. A target-response calculation used as a purported structural gate belongs to analysis unless separately authorized.

Return the faithful portion of the implementation, unresolved scientific decisions, document/access gaps and the supported interpretation in the existing `review.md` or `final-review.md`. Compare those findings with every readiness claim. State whether the calculation is fully specified but awaits a fact, or still requires a scientific choice such as an estimator. Use [bounded critique](critique.md#repair-verify-and-stop) to verify material repairs; do not fill them during final polishing.

## Make continuation executable

Write a ready-to-use request in `NEXT.md` naming the current dossier/revision, existing authorization, consumed cycles and the smallest unresolved decision. Choose the branch supported by current evidence; remove implementation requests for a direction the evidence says to stop. Preserve owner answers, including unknowns. For example:

> Continue from [dossier path/revision], [brief] and [NEXT]. Resolve [specific scientific decision] using [available authorized evidence] and produce [bounded output]. Existing scope permits [planning actions]. [Relevant limit or consumed allowance] remains. This request does not authorize real candidate target-effect execution.

The final reader checks this request with the dossier and summary. Resuming one question does not require rebuilding unrelated knowledge or regenerating candidates.
