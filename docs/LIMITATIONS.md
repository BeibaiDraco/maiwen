# Validation and limitations

**This is a research-preview candidate.** The package implements a scientific planning method; it does not guarantee novelty, answerability, useful precision or publishability. An independent context can find errors but may share the author's model biases. Source evidence, design reasoning and reproducible checks remain decisive.

## Scientific evidence

The current method incorporates improvements from neuroscience development trials. A full IBL trial on `0.2.0-alpha.3` used a 36-session planning view on each of Codex and Claude Code. It produced useful conditional directions and also exposed material scientific and process defects. Permission denials limited the Claude run. These are development observations, not a controlled comparison of hosts or proof of improvement over a general agent.

Alpha.4 introduced decision-focused checking and repairs, and alpha.5 added a bounded return to generation. Their focused fictional cases and valid controls exercised specific behaviors. They did not constitute a new full real-data discovery. This beta candidate packages that method with user documentation and corrects the scope of one fictional delivery example; it does not relabel the earlier trial as a beta result. The [curated IBL case](../examples/ibl-conditional-question.md) preserves its historical version and conditional scope.

Evidence remains concentrated in neuroscience. General wording and a domain-neutral package do not establish effectiveness in every field. The workflow cannot exhaust an entire literature, and inaccessible sources or ambiguous owner information can prevent a recommendation. A reviewed bank must be checked for applicability in a new setting.

## Host and installation scope

The intended environments are local Codex and Claude Code sessions with native independent subagents and appropriate data/source tools. Installer checks establish loading and relocatable resources. A bounded first-use exercise establishes only the behaviors actually observed; it is not scientific validation. A complete desktop App workflow, all operating systems and future host versions are not established by a local CLI check. Candidate checks used Codex CLI 0.163.0 and Claude Code 2.1.303. Both installed the four-skill package. Each completed one bounded fixture-only input/card exercise with a native independent reviewer and English saved artifacts (8.49 and 3.98 minutes respectively). Codex loaded the installed cache; Claude loaded the same exported package using its session-local plugin option after installer validation. The exercise deliberately stopped before field research, pattern learning or question generation. Resume instructions were inspected; a separate resumed model session was not run.

The Claude card received repairs after review without an independent recheck of the repaired card, and its final summary overgeneralized prior exposure into a need for new data. The latter prompted a narrow clarification now present in the planning guide. That clarification and the corrected fictional measurement example received independent static review, not another live host trial. Installation, refresh/removal and package checks passed; these observations do not establish perfect workflow compliance or scientific quality.

The host controls model access, account usage, tools, permissions and context limits. Maiwen does not supply model credits, bypass permission restrictions or guarantee that a required tool is available. Without independent contexts, it can produce useful preparation and an honest review handoff, not the complete reviewed workflow.

## Planning boundary

Authorized planning may inspect data structure, counts, coverage, marginal distributions and suitable synthetic cases. The candidate's real target-effect analysis, significance search and confirmation data are outside the default workflow. Prior exposure relevant to a later question must be recorded. Files and role instructions are organizational aids, not an access-control sandbox.
